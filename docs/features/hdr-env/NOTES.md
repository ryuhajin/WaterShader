# hdr-env — HDR 환경맵 + 하늘 기반 조명 보정 (회고 기록)

> 2026-10-03 · feature/hdr-env

캡처 조건은 이전 feature와 동일(1280×720, `t = 12s`, 고정 샷 5 × 프리셋 3, 무인 모드).
재현: `WaterShader.exe --capture-feature hdr-env --capture <label>` → `captures/<label>/`, 비교 시트 `compare/`.

---

## 배경 — linear-hdr에서 남은 문제

linear-hdr로 계산·출력 파이프라인은 정석이 됐지만 **입력(하늘)이 여전히 LDR**이었다.
- 하늘 JPG는 이미 한 번 톤매핑된 사진이라, 우리 톤매핑을 또 거치면 바뀐다(**이중 톤매핑**). 그래서 노출을 "원본 사진과의 오차"로 피팅해야 했고, 채널별 ACES는 하늘을 표백했다.
- LDR에선 태양도 255에서 잘려 있어 실제 밝기를 모른다 → 태양 글린트 강도를 **감으로**(12~22) 정했다.

**목표:** 하늘을 장면 휘도 그대로인 HDR 원본으로 바꾸고, 태양·하늘의 실제 밝기에서 조명을 끌어낸다.

---

## Step 0 — 안전장치 + before (`captures/before/`)

- **실수 캡처 확인:** UI의 Capture Set 버튼을 실수로 눌렀지만 기본 라벨이 `manual`이라 `water-polish/captures/manual/`이 **새로 생겼을 뿐**, 기존 캡처는 덮어쓰지 않았다(`git status`로 확인, 변경된 추적 파일 없음). 폴더는 삭제.
- **재발 방지:** 버튼 → 확인 팝업(저장 위치 표시) 2단계, UI 캡처는 기존 폴더가 있으면 `<label>_2`, `_3`…로 새 폴더. 명령줄 `--capture`는 의도적 재촬영이므로 기존 동작 유지.
- before = linear-hdr step3 상태(LDR 하늘 + 리니어 + ACES hue-preserving).

## Step 1 — HDR 큐브맵 (`captures/step1_hdr_env/`)

### 해결 방식

- 소스: Poly Haven CC0 4k `.hdr` — `grasslands_sunset`(Basic), `the_sky_is_on_fire`(Sunset), `spiaggia_di_mondello`(Tropical). `grasslands_sunset`은 기존 `skybox.dds`와 같은 장면(같은 나무·지평선)으로 보여 원본으로 추정.
- `tools/equirect_to_cube.ps1` 확장:
  - Radiance `.hdr` 직접 파싱(RGBE + 신형 RLE 스캔라인) → **linear 복사휘도 float**.
  - float 큐브(RGBA32F, DX10 헤더) → texconv `BC6H_UF16` + 밉(1024², 8 MB). LDR 경로(RGBA8 → BC7)는 그대로 유지.
- 로더: `CubemapTexture::Initialize(..., srgb)` — **HDR은 `FORCE_SRGB` 없이.** BC6H/float엔 `_SRGB`가 없고 값 자체가 linear다. LDR 하늘 3종도 남겨서(LDR vs HDR 비교용) 환경 드롭다운에 6개.
- 노출: 도구가 로그 평균 휘도로 key 0.18 노출을 제안(meadow −0.96, sunset −0.27, beach −0.81). **이중 톤매핑이 없으니 "원본 사진과 맞추는" 피팅이 더 이상 필요 없다.**

### 과정에서 걸린 것 — 태양 방향 측정

- 처음엔 "최대 휘도의 1% 이상인 텍셀"의 가중 중심을 태양으로 봤다. 태양 원반이 있는 하늘(peak 15,766 / 98,090)은 정확했지만, **원반이 안 보이는 노을(`the_sky_is_on_fire`, peak 38)**은 밝은 구름 전체가 잡혀 태양이 **고도 77°**로 나옴 → 회전이 틀어짐.
- 임계값을 **최대의 25%**로 올려 해결(원반이 있으면 원반만, 없으면 가장 밝은 글로우만) → 고도 4.0°.
- 부수 발견: LDR 버전은 이 노을의 "태양"을 yaw 103.8°로 측정했었는데 HDR의 실제 최대 휘도는 그보다 ~40° 옆. **잘린 JPG에선 255로 뭉개진 넓은 영역의 중심이 진짜 최대점과 다르다.**

### 결과

- 초원: 하늘이 회색으로 바래 있던 LDR과 달리 **위는 파랗고 태양 주변은 분홍**인 실제 그라데이션 + 태양 원반이 보임. 하늘 채도 0.11 → 0.40.
- 노을: 채도 0.29 → 0.83(노출 −0.27에서는 과노출 16.5% → Step 2에서 조정).

## Step 2 — 태양 분리 + 하늘에서 조명 보정 (`captures/step2_calibrated/`)

### 문제 1 — 태양이 두 번 계산됨

HDR 하늘에는 태양 원반이 실제 밝기로 들어 있다. 물은 하늘을 반사하므로 **하늘 속 태양이 이미 빛의 길을 만든다** + 그 위에 해석적 글린트가 같은 태양을 또 더한다.
- 측정: 초원 `ocean_sunward`의 빛의 길에서 거의 흰색(≥235) 픽셀이 해석적 글린트를 끈 상태에서도 **8.0%**, 켜면 9.3% — 대부분이 이미 하늘 반사에서 온다.
- 선택지: (A) 하늘에서 태양을 빼고 해석적 태양으로 일원화, (B) 해석적 글린트 제거, (C) 둘 다 두고 약하게. **(A)**를 택함 — 실제 엔진 방식이고 태양 방향 슬라이더가 계속 의미를 가진다.

### 해결 1 — 도구에서 태양 분리·측정

- 태양 주변 2.5° 원뿔 안에서 **주변 하늘(2.5~5° 고리 평균)의 4배를 넘는 텍셀만 그 값으로 클램프** → 원반(하늘의 수천 배)은 제거, 그 주변의 글로우(aureole, 산란광)는 매끄럽게 유지. 제거된 초과분을 입체각으로 적분 = **태양 조도**.
- **첫 시도 실패:** 원뿔 전체를 고리 평균으로 채웠더니 하늘에 **평평한 분홍 원판**이 생겼다(글로우까지 지워짐). 코어만 클램프하는 방식으로 변경.
- 태양이 안 보이는 하늘(태양 조도 < 하늘 조도의 5%)은 분리하지 않음 — 노을은 글로우가 곧 빛의 길.

| 하늘 | 태양 (E/π, linear) | 하늘 ambient (E/π, 위쪽 평면) | 비고 |
|---|---|---|---|
| 초원 | (0.422, 0.080, 0.010) | (1.018, 1.276, 1.636) | 고도 3.3°, 연무 속 붉은 해 — 하늘이 태양보다 8배 밝음 |
| 노을 | 없음 | (0.899, 0.733, 1.062) | 원반 안 보임, 분리 안 함 |
| 해변 | (1.668, 1.742, 1.453) | (0.182, 0.317, 0.601) | 맑은 낮, 태양이 하늘의 약 5.5배 |

### 해결 2 — 측정값을 같은 단위로 연결

| 항목 | 이전 | 이후 |
|---|---|---|
| 태양·ambient 색/강도 | 눈으로 고른 값 | 측정 조도 / π (Lambert: `albedo · light · N·L`가 `albedo/π · E`가 되게). `Calibrate Lights From Sky` 버튼 = 프리셋 값 |
| 하늘의 태양 | 텍스처 속 원반 | 스카이박스 셰이더가 해석적으로 그림: 복사휘도 = E / Ω, Ω = 2π(1 − cos 0.2665°) |
| 태양 글린트 | `pow(R·L, n) × 12~22` (임의) | **에너지 정규화 로브** `(n+2)/2 · pow(R·L, n) · F · light` — 반사되는 태양 에너지 = F·E로 n과 무관. `sunGlintIntensity`는 배율(1 = 물리값) |
| Blinn-Phong 광택 | 0.2~0.25 | **0** — 같은 태양의 세 번째 반사였음 |

- 결과적으로 **하늘에 보이는 태양 = 물을 비추는 태양 = 물에 반사되는 태양**이 하나의 측정값에서 나온다.

### 과정 — 재튜닝

- 보정된 ambient(초원 1.64)가 기존 손튜닝 값(약 0.3~0.5)보다 훨씬 커서 Basic 몸체가 **밝은 하늘색 페인트**처럼 됨. 실제 깊은 물의 몸체 산란은 몇 % 수준 → 몸체색을 크게 낮춤: Facing (0.10,0.36,0.40) → (0.03,0.20,0.21), Grazing (0.06,0.46,0.50) → (0.02,0.26,0.26).
- 정규화 글린트는 로브가 좁으면(n = 800) 빛의 길이 수평선 띠로만 남음 → Basic n = 300, Tropical 500. 정규화 덕분에 로브를 넓혀도 총 에너지는 그대로이고 **더 넓게 흩어질 뿐**(손튜닝 때처럼 강도를 같이 만질 필요 없음).
- Sunset 노출 −0.27(key) → −1.2: key 노출은 "평균 장면"을 중간 회색으로 맞추는데, 노을은 원래 어두운 장면이다.
- 목표 수치 비교 시 주의: before의 수치는 **바랜 LDR 하늘** 기준이다. HDR 하늘이 실제로 더 파랗고 분홍이라, 비스듬한 각도의 물(반사 지배)이 before와 달라지는 건 정상(예: 노을 물이 따뜻한 색 H 3~11°, S 0.17~0.19로 — bench-tools 5번에서 원했던 "노을빛 반사").

### 검증 (영역 측정)

| 영역 | before (LDR) | step1 (HDR) | step2 (보정) |
|---|---|---|---|
| 노을 하늘 채도 / 거의 흰색 비율 | 0.29 / 0% | 0.83 / 16.5% (과노출) | **0.70 / 4.8%** |
| 초원 하늘 채도 | 0.11 | 0.40 | 0.40 |
| 초원 태양 주변 채도 | 0.20 | 0.63 | **0.78** (글로우 유지 + 해석적 원반) |
| 초원 빛의 길(wide) 거의 흰색 비율 | 0.5% | 3.8% | **6.8%** |
| 해변 하늘 채도 | 0.42 | 0.59 | 0.59 |
| 최대 밝기(태양·글린트) | 191~223 | 255 | 248~255 |

- LDR에선 하늘의 가장 밝은 곳도 191~223에 머물렀다(사진이 이미 압축됨). HDR에선 태양·글린트가 실제로 화면의 최대 밝기에 도달하고, 하늘은 색을 유지한다.
- 성능(Release, VSync off): GPU bench 0.01 ms, ocean 0.18 ms — linear-hdr과 동일(BC6H 샘플링·태양 원반 비용 측정 불가 수준). bench FPS는 4805로 이전 측정(6036)보다 낮았지만 GPU·CPU 시간은 같아서, 차이는 측정 범위 밖(Present/컴포지터)으로 판단.

### 교훈

- **HDR 입력은 "더 예쁜 텍스처"가 아니라 단위의 문제다.** 하늘이 실제 밝기를 가지면 노출 피팅, 이중 톤매핑, 감으로 정한 글린트 강도 같은 보정이 필요 없어지고, 조명값을 측정해서 얻을 수 있다.
- 같은 광원이 여러 경로(하늘 반사, 해석적 스펙큘러, Blinn-Phong)로 들어오면 **중복 계산**이 생긴다. 광원마다 "어디서 한 번만 계산되는가"를 정해야 한다.
- 측정 알고리즘은 극단적인 입력(태양이 안 보이는 하늘)에서 깨진다. 임계값·클램프 방식은 실패 사례를 보고 고쳤고, 그 과정을 기록했다.
- 물리 단위로 바꾸면 기존 아트 값(몸체색)은 다시 맞춰야 한다 — 이번엔 "깊은 물의 몸체 산란은 몇 %"라는 물리적 기준이 있어 방향이 분명했다.
