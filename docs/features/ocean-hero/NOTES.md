## 1. 출발점 — `ocean_aerial`의 근경 → 원경 전환

포트폴리오 PDF 메인으로 쓸 `ocean_aerial` + Basic(`captures/before/basic_ocean_aerial.jpg`)에서 근경 → 원경 전환이 부자연스러웠다.
글린트가 맺히는 모습은 사용자가 마음에 들어 해서 유지 대상이다.

| 구간 | 보이는 것 | 원인 |
|---|---|---|
| 근경 | 노멀맵 잔물결 + 메시 파도 | — |
| 중경 | 일정 간격의 가로 어두운 점선 줄 | 메시 페이드(8λ → 14λ) 이후 픽셀 구간에서 작은 파도 2개(λ 1.4, 0.92)의 사인 마루가 교차해 규칙 격자가 된다. Basic 바람(−105°)이 시선(yaw 15)과 거의 평행해서 격자가 가로 줄로 눕는다 |
| 원경 | 나무·하늘이 또렷이 비치는 거울 띠 | 거칠기 구간의 σ²는 글린트 폭만 넓히고 하늘 반사는 흐리게 하지 않는다(wave-far-normals step4 결정). 대기 원근도 없다 |

- **진단 근거:**
  - 디버그 뷰 2(월드 법선)에서 격자 무늬가 보였다.
  - `--far-waves off`로 찍으면 격자와 줄무늬가 사라지고 근경 글린트도 그대로였다.
- **바람을 −125°로 돌렸을 때:** 같은 격자가 시선 쪽으로 서면서 **방사형 줄무늬**로 바뀌었다.
  - 노멀맵 A를 0 / 1 / 정렬 끔으로 바꿔도 그대로였다. 원인은 노멀맵이 아니다.

## 2. 셰이더 — Ocean Detail

### 2-1. 손댄 곳 (`PixelShader.hlsl`, 상수 `g_DetailParams`, `g_DetailParams2`, `g_FarParams.yzw`)

정점 셰이더(Gerstner 변위)와 wave 상수 배열은 바꾸지 않았다. 지오메트리는 그대로이고, 아래 항목은 모두 픽셀 단계의 **조명용 법선 / 거칠기 / 최종 색**만 바꾼다.

| 항목 (UI: Water › Ocean Detail) | 위치 (PSMain 흐름 순) | 하는 일 | 법선에 미치는 영향 | 파라미터 (기본 = 꺼짐) |
|---|---|---|---|---|
| Gust patches | 노멀맵 A/B 블렌드 직후 | 월드 XZ value noise 2옥타브 g(−1~1), 바람 방향으로 `wave[0].speed × 1.5`로 흐름 | 리플 기울기 ×(1 + 세기·g) | `gustStrength` 0, `gustScale` 30 |
| Far ripple glitter | 같은 곳 | `smoothstep(1, 5, mip)` × 맵 경사 분산 × 세기² × 계수를 σ²에 더함 | **없음** — σ²만 늘려 글린트·하이라이트 로브를 넓히고 피크를 낮춤 | `rippleRoughness` 0 |
| Far wave crests | `EvaluateFarWaves` | 픽셀 구간 가중치 w 중 (1 − keep)을 거칠기 구간으로 넘김 | 원경 픽셀 기울기 감소 | `farWaveCrests` 1 |
| Gust patches (파도) | 파도 법선 `baseNormalWS` 직후 | 위쪽(0,1,0)과 lerp | 파도 기울기 ×(1 + 0.5·세기·g) | (위와 같음) |
| Horizon haze | 태양 글린트 더한 뒤 | 같은 방위 앙각 ~10° 하늘색(mip 7)과 보간 | **없음** — 최종 색만 | `hazeStrength` 0, `hazeDistance` 150 |
| 디버그 7 | 끝 | R = 리플 거칠기 ×20, G = 돌풍, B = 연무 | — | — |

- **리플 경사 분산:** jpg 원본에서 (x² + y²) / z²의 평균을 쟀다.
  - 값: 0 Diagonal 0.060 / 1 Soft swell 0.0125 / 2 Soft chop 0.0072 / 3 Long streaks 0.023 / 4 Fine chop 0.062.
  - `kNormalMaps.slopeVariance`에 두고, 매 프레임 `g_FarParams.zw`로 보낸다. 프리셋에는 저장하지 않는다.

### 2-2. 문제 4 — 분기만 넣어도 기존 화면이 바뀜 → 별도 셰이더 변형

- **증상:** 처음에는 새 항목을 모두 `if (값 > 0)` 분기 안에 넣었다. 값이 0인데도 기존 18장 중 9장이 일부 픽셀에서 1~4 레벨 달라졌다.
- **원인 분리:**
  - 이전 픽셀 셰이더 + 새 C++로 찍으면 0장이 달랐다 → 원인은 셰이더 쪽이다.
  - 연무 블록 하나만 남겨도 18장이 모두 달라졌다.
  - 분기를 타지 않아도, 코드가 늘면 드라이버의 명령어 배치(FMA 결합 등)가 바뀐다.
- **해결:**
  - `ColorShader::Reload`가 같은 파일을 두 번 컴파일한다: 기본(정의 없음) / `OCEAN_DETAIL=1`.
  - Ocean Detail 값이 하나라도 켜져 있거나, crests < 1이거나, 고해상도 LOD 배율 ≠ 1이거나, 디버그 7이면 변형을 바인딩한다.
  - 추가 코드는 모두 `#if OCEAN_DETAIL` 안에 있다. 노멀맵 샘플처럼 기존 줄을 바꿔야 하는 곳은 `#else`에 원래 줄을 그대로 둔다.
- **검증:** Basic / Sunset / Tropical 18장이 `captures/before`와 **해시까지 같다**. 매 수정 후 다시 확인했다(마지막은 고해상도 LOD와 PNG 수정 뒤).

### 2-3. 문제 6 — Toksvig 거칠기가 동작하지 않음 → 측정값 사용

- **증상:** mip 평균 법선의 길이로 잃은 경사를 추정했더니(Toksvig) 디버그 7의 R이 거의 0이었다.
- **원인:** 이 DDS들의 mip은 재정규화되어 있어 평균 법선의 길이가 줄지 않는다.
- **해결:** 맵별 경사 분산을 측정하고, `CalculateLevelOfDetail`로 구한 mip 레벨만큼 σ²에 더한다.
  - mip 1까지는 0이라 근경은 그대로다.

### 2-4. 문제 5 — 연무가 방사형 줄무늬를 만듦

- **증상:** 연무만 켠 캡처(iso_haze)에 방사형 줄무늬와 대각선 띠가 생겼다.
- **원인:** 수평선 바로 위(앙각 2.3°, mip 0)를 샘플했다. 이 하늘들의 수평선에는 언덕·나무가 있어 화면의 열마다 다른 색을 집었다.
- **해결:** 앙각 ~10°, 흐린 mip 7에서 샘플한다.

### 2-5. 돌풍 크기

처음 값(gustScale 40, 대비 ×2.6)은 프레임에 패치가 하나뿐이고 경계가 딱딱했다(디버그 7). 기본 대비를 ×1.6으로 낮췄다. 샘플은 15로 찍었다.

## 3. 샘플 비교와 기각한 시도 (`make_samples.ps1`)

1차 비교 구도(`cameras_candidates.txt`)는 4개였다. C1 `ocean_aerial`, C2 같은 위치 태양 정면, C3 고공 사선, C4 저공 광각.

| 변형 | 내용 | 관찰 |
|---|---|---|
| w0 | Basic | 기준 |
| w1 | Basic + 원경 글리터 0.3, 돌풍 0.4 / 15, 연무 0.35 / 150 | 가로 줄이 옅어지고 원경 거울 띠가 연무로 이어짐. 근경 글린트 그대로 |
| w2 | w1 + 바람 −125°, chop 0.2, crests 0.6 | 줄이 비스듬히 흐르고 격자가 약해짐 |
| w3 | w2 + spread 32, size 4.2, crests 0.35, Far spread 0.35, 돌풍 0.55, 연무 0.45 | 가장 잔잔함. 글린트가 덩어리로 뭉침 |

**기각한 시도**
- **바람 −140°, spread 45°, 노멀맵 Soft chop / Fine chop:** 다이아몬드 격자가 생기고 글린트가 큰 얼룩이 됐다. spread가 35°를 넘으면 격자가 생긴다(wave-far-normals와 같은 결론).
- **파도 높이 0.035, chop 0.15:** 물이 매끈해져 글린트가 넓은 판으로 번졌다.
- **리플 세기 0.55:** 비스듬한 노멀맵 무늬가 도드라졌다.
- **원경 글리터 1.0:** 글린트가 흰 판으로 번져 반짝임이 사라졌다. 0.3이 적당했다.
- **crests 0 / 0.3 단독:** 격자는 사라졌지만 원경 글린트가 크게 번졌다. Far spread를 함께 낮춰야 한다.

## 4. 문제 7 — hero는 프리셋이 아니라 카메라 샷

- **잘못된 1차 구현:** 사용자 선택(C1 + w1)을 4번째 셰이더 프리셋 "Hero"와 카메라 슬롯 4에 저장했다.
- **사용자 의도:** hero는 **고정 카메라 샷 하나**다. 그 샷에서 Basic / Sunset / Tropical이 같은 위치를 공유하고, 각자의 태양·색으로 보여야 한다.
- **수정:**
  - 4번째 테마를 제거했다(`kPresetThemeCount` 3, `assets/shader_presets.txt` 원복).
  - 덮어썼던 카메라 슬롯 4를 사용자 값으로 되돌렸다.
  - 고정 샷 **`ocean_hero`**를 추가했다: (−5.38, 6, −20.09), pitch 14, yaw 18, 화각 44.
- **샷 값 역산:** 사용자 참고 화면(하늘 약 1 : 물 약 3)에서 구했다.
  - 기준: 물/언덕 경계 21%, 언덕선 7%, 반사 띠 끝 36%, 글린트 중심 가로 72%.
  - 위쪽 경계는 진짜 수평선이 아니라 그리드 끝(수평선 아래 atan(h / 400))이다. 그래서 높이도 경계 위치를 바꾼다.
  - 시도 1: 높이 2.5~6 / 화각 50 → 경계 23%.
  - 시도 2: 높이 8~12 → 경계 26%, 반사 띠가 너무 넓다.
  - 시도 3: 높이 6 / 화각 44에서 네 기준이 모두 맞았다.
- **Ocean Detail:** 기능과 UI만 남기고 코드 기본값은 꺼짐이다(사용자 결정).

### 5-1. 문제 8 — 2560×1440이 창 화면보다 뿌옇게 보임

- **증상:** 같은 설정을 720p로 찍으면 실행 창과 색이 같았다(물 평균 RGB 68/106/129 대 68/107/130). 2560×1440은 평균색은 같은데 명암 대비가 떨어졌다.
  - 물 영역 밝기 표준편차: 37.2 → 32.4
  - 중경: 39.7 → 32.8
- **원인:** 픽셀 구간 경계(파장당 16 → 8 px)와 노멀맵 mip이 **화면 픽셀** 기준이다.
  - 해상도가 2배면 가는 마루 줄이 2배 멀리까지 남는다. 720p에서는 그 자리가 반사 띠였다.
  - 노멀맵은 한 단계 고운 mip을 읽는다.
  - 하늘 반사와 물 색이 잘게 섞인 결과를 축소해서 보면 회색으로 평균된다.
- **해결:** `--render-size`일 때만 `lodScale = 렌더 높이 / 720`을 보낸다. OCEAN_DETAIL 변형이 두 곳에 적용한다.
  - `EvaluateFarWaves`의 footprint에 배율을 곱한다.
  - 노멀맵 샘플과 `RippleLostFraction`에 mip bias log2(배율)를 준다.
  - 창 렌더(배율 1)는 영향이 없다. 0이 들어오면 꺼짐으로 처리해, 이전 C++로 실행 중인 앱이 핫 리로드해도 깨지지 않는다.
- **검증:** 1440p 표준편차 37.6, 중경 40.3이 됐다(720p 37.2 / 39.7). 같은 인상에 가장자리만 선명하다.

### 5-2. 문제 9 — PNG가 뷰어에서 하얗게 뜸

- **증상:** 저장된 PNG를 Windows 뷰어로 열면 하늘·나무까지 전체가 밝고 뿌옇게 보였다. 제작 측 검사 도구(GDI+)는 감마 태그를 무시해서 차이가 안 보였다.
- **원인:**
  - 백 버퍼는 `R8G8B8A8_UNORM`인데 tonemap 패스가 sRGB로 인코딩한 값을 담는다. ImGui가 같은 버퍼에 그리므로 `_SRGB` 뷰를 쓰지 않는다.
  - DirectXTK `SaveWICTextureToFile`은 UNORM 형식을 리니어로 보고 PNG에 `gAMA 1.0`을 기록했다.
  - 이 태그를 따르는 뷰어가 이미지를 한 번 더 밝게 풀었다.
- **해결:** PNG 저장에 `forceSRGB = true`를 줬다. 이제 `sRGB` 청크와 gAMA 0.45455가 기록된다.
  - JPEG 경로는 기존 캡처와 해시 비교를 할 수 있도록 바꾸지 않았다.
- **검증:** 새 PNG의 IDAT는 이전 파일과 바이트 단위로 같고, 태그만 바뀌었다.

**최종 파일:** `captures/final_slot1/basic_slot1.png` (2560×1440, sRGB 태그)

## 6. 한계 / 남은 것

- **연무는 물에만 적용된다.** 언덕이 보이는 구도에서 연무를 켜면 물과 언덕 사이에 경계가 생긴다(`compare/ocean_hero.jpg`의 w1~w3). 하늘 셰이더에도 같은 연무를 거는 것은 미구현이다.
- **화면 위쪽 경계는 그리드 끝(±400)이다.** `ocean_hero`와 슬롯 1 모두 반사 띠와 언덕 사이 선이 그대로 보인다.
- **슬롯 1과 `ocean_hero`는 서로 다르다.** 사용자가 최종 컷으로 고른 슬롯 1은 yaw −163.2(나무 쪽)이고, ocean Basic의 태양도 그 방향(210.2)으로 옮겼다. 고정 샷 `ocean_hero`(yaw 18)는 그대로다.
  - Sunset / Tropical의 태양은 yaw 35 근처라, 슬롯 1 방향에서는 글린트가 화면에 들어오지 않는다.
- **UI `Save Current` 경로:** 사용자가 직접 사용해 ocean Basic과 슬롯 1이 저장되는 것을 확인했다.
