# Wave Occlusion — 7단계 파도와 수면 가림

> Branch: `feature/wave-occlusion` · Status: draft · Updated: 2026-11-07
> waterfront 업그레이드 7단계. 앞 단계: [../normal-gbuffer/NOTES.md](../normal-gbuffer/NOTES.md)

## 1. Goal / Visual Target

- **한 문장 요약:** 테스트 장면에 Gerstner 파도를 다시 켜고, 수면이 움직이면서 깨지는 세 가지를 고친다: **가까운 파도를 먼 파도가 덮는 문제**, **파도 높이를 무시한 수심·잠김 판정**, **물 영역 가장자리의 틈**.
- 노멀맵 잔물결은 6단계부터 이미 켜져 있다 (PLAN의 "노멀맵 → Gerstner 순" 중 앞부분). 이번 단계는 기하 파도(Gerstner)다.
- **스코프 가드 — 만들지 않을 것:** 굴절(8), 물체 반사(8B), 거품 모양 변경(수면 고리는 언리얼 거리장 단계), 성능 측정(요청 시만), 기존 바다 화면 변경.

## 2. 문제와 방법

**① 가림 — 가장 가까운 수면만 그리기**

```text
바다 모드:    물이 깊이를 쓴다 → 앞 파도가 뒤 파도를 가림 (문제없음)
테스트 장면:  2단계부터 물이 장면 깊이를 "읽어야" 해서 깊이 쓰기를 껐다
              → 파도가 겹치는 곳에서 나중에 그려진 삼각형이 이김 (먼 파도·파도 뒷면이 앞을 덮을 수 있음)
```

같은 깊이 텍스처를 읽으면서 동시에 쓸 수는 없다(2단계). 그래서 **물 전용 깊이 버퍼**를 따로 둔다.

```text
1. 장면 깊이를 물 깊이 버퍼로 복사                (불투명 물체의 깊이부터 시작)
2. 물 깊이 프리패스: 물 메시를 깊이만 그림 (LESS, 쓰기)  → 각 픽셀에 "불투명 vs 가장 가까운 수면" 중 앞의 것
3. 물 색 패스: 물 깊이 버퍼를 읽기 전용으로, 같음(EQUAL) 테스트
              → 가장 가까운 수면 조각만 통과, 비싼 물 셰이더가 픽셀마다 한 번만 돈다
   (장면 깊이 SRV는 그대로 원래 불투명 깊이 = 수심·경로 계산용)
```

비교용 가림 모드 3가지:

| 모드 | 방법 | 결과 |
|---|---|---|
| None | 6단계까지 그대로 (쓰기 없음) | 겹친 곳이 그리는 순서에 좌우됨 |
| Single pass | 물 깊이 버퍼에 색 패스가 직접 쓰기 (LESS) | 결과는 맞지만, 겹친 조각을 여러 번 셰이딩 |
| **Prepass** (기본) | 위 1~3 | 결과는 Single pass와 같고 셰이딩은 한 번 |

**② 파도 높이를 반영한 수심·잠김**

```text
지금:   수심 = (이 물 픽셀의 수면 높이) − (물 너머 표면 높이)
바꿈:   수심 = (물 너머 표면 바로 위의 수면 높이) − (물 너머 표면 높이)
```

- 거품 띠가 기둥에 붙은 채로 파도를 따라 오르내리고, 램프 수심 기준도 실제 수면을 따른다.
- Gerstner는 수면을 옆으로도 민다 (`x = x₀ + 옆 이동(x₀)`). "이 XZ 위의 수면 높이"를 구하려면 거꾸로 x₀을 찾아야 해서, `x₀ ← x − 옆 이동(x₀)`를 3번 되풀이한다 (고정점 반복). 정점 셰이더와 같은 파도 함수를 `Waves.hlsli`로 옮겨 함께 쓴다 (PLAN "공유된 변위 계산").
- 물 너머 표면이 그 자리 수면보다 위에 있으면(파도 골 위로 드러난 계단) 물 밖으로 본다.

**③ 정답지도 파도를 따른다**

- Scene Debug 1·2(정답지 수심)를 `같은 파도 높이 − 표면 높이`로 바꾼다. 3단계의 숫자 비교 도구를 파도가 있는 상태에서도 쓸 수 있다.

**④ 물 영역 가장자리**

- 수평 이동 때문에 가장자리 정점이 안쪽으로 끌려가 틈이 생긴다. 영역 끝 1m에서 파도를 0으로 줄인다.

**디버그 / 도구**

| 이름 | 내용 |
|---|---|
| View 창 Lab Waves | 기본 켬으로 바꿈 (끄면 6C 화면) |
| Water occlusion | None / Single pass / Prepass |
| Debug Mode 25 | Water surface height above the receiver (m) — ②의 값 |
| CLI | `--lab-waves on\|off`, `--water-occlusion none\|single\|prepass` |
| 파도 값 | Surface 창(4) Waves의 크기·높이·방향을 그대로 쓴다 (바다 프리셋과 공유). 자동 캡처는 UI를 못 만지므로, 파도를 키운 검증 캡처는 높이만 바꾼 프리셋 파일을 `--preset-file`로 넘긴다 (6단계 칠한 물색 검사와 같은 방식) |

## 3. Acceptance Criteria

**에이전트 검증**

- [ ] 빌드 경고 0, 디버그 레이어 경고 0, 기존 샷 21장 바이트 동일
- [ ] Lab Waves 끔 → 6C 화면과 바이트 동일
- [ ] 가림: Prepass 화면 = Single pass 화면 (바이트 또는 1레벨 이내), None과는 겹친 곳에서 다름. 낮은 시점 전후 캡처
- [ ] 높이 역산: 3번 반복 후 남는 옆 오차가 1mm 이하 (디버그로 측정)
- [ ] 파도가 있을 때 복원 수심(12) vs 정답지(Scene Debug 2): 3단계와 같은 허용치 안
- [ ] 거품: 거품 픽셀의 정답지 수심(파도 기준) ≤ 폭
- [ ] 가장자리 틈 없음 (물 영역 경계 캡처)

**사용자 검증**

- [ ] 낮은 시점에서 먼 파도가 가까운 파도를 덮지 않는다 (None ↔ Prepass 비교)
- [ ] 기둥의 거품 띠가 파도를 따라 오르내린다
- [ ] 물 깊이 프리패스가 왜 필요한지(같은 깊이를 읽고 쓰지 못함, 셰이딩 한 번) 설명할 수 있다

## 4. Notes

- 언리얼 대응: Single Layer Water는 물을 별도 패스로 그리고, 물 깊이를 따로 다룬다. 15단계(RenderDoc)에서 확인.
- 성능 측정은 하지 않는다 (사용자 지시 2026-11-07). Prepass의 이득(셰이딩 한 번)은 개념과 화면으로만 다룬다.
