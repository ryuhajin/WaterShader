# Contact Foam — 6B단계 접촉 거품

> Branch: `feature/contact-foam` · Status: draft · Updated: 2026-11-07
> waterfront 업그레이드 6B단계. 앞 단계: [../surface-reflection/NOTES.md](../surface-reflection/NOTES.md)

## 1. Goal / Visual Target

- **한 문장 요약:** 물체가 수면을 뚫는 곳(기둥 둘레, 계단·승강장 가장자리)에 **흰 거품 띠**를 그려, 위에서 내려다보는 게임 카메라에서도 물체가 물에 잠겨 있다는 게 읽히게 한다.
- 출발점: 6단계 관찰. 위에서 볼 때 기둥 근처 반사 비율이 3~5%라 Fresnel만으로는 수면선이 보이지 않는다 ([NOTES 관찰](../surface-reflection/NOTES.md)).
- 띠의 폭은 **미터 단위**다. 카메라를 돌리거나 멀어져도 같은 폭이다.
- **얕고 평평한 바닥에는 거품이 없다.** 레일 머리(수심 8cm)나 침목(23cm) 위를 거품으로 덮지 않는다.
- **스코프 가드 — 만들지 않을 것:**
  - 파도 마루 거품(화이트캡), 물보라·파티클
  - 수면 바깥쪽으로 퍼지는 진짜 고리(물체에서 수평 거리로 그리는 링). 화면 공간에서는 구할 수 없다 (5절)
  - 파도와의 통합 (7단계에서 재검증)

## 2. HLSL 접근법 / 수식 / 의사코드

**① 경계 찾기 — 앞 패스의 깊이를 다시 쓴다**

```text
수심 = 수면 높이 − 받는 표면 높이        // 3단계에서 이미 계산 (2단계 장면 깊이 → 위치 복원)
경계 가까움 = 1 − 수심 / 거품 폭          // 수면 바로 아래 = 1, 폭보다 깊으면 0
```

**② 평평한 얕은 바닥 걸러 내기 — 기울기**

수심만 보면 얕고 평평한 바닥 전체가 경계로 잡힌다.

| 받는 표면 | 수심 | 수심만 볼 때 (폭 0.25m) | 기울기까지 볼 때 |
|---|---|---|---|
| 기둥 벽, 수면 바로 아래 | 0 ~ 0.25m | 거품 | 거품 (벽 = 가파름) |
| 레일 머리 (Waterfront) | 0.08m | **레일 전체가 거품** | 거품 없음 (평평) |
| 침목 (Waterfront) | 0.23m | **침목 전체가 거품** | 거품 없음 |
| 0.2m 받침대 윗면 (Water Lab) | 0.2m | **윗면 전체가 거품** | 거품 없음 |
| 받침대 옆면, 수면 바로 아래 | 0 ~ 0.25m | 거품 | 거품 |

```text
받는 표면의 법선 = 이웃 픽셀의 복원 위치 차이로 계산 (오른쪽·아래 이웃, 깊이 차가 작은 쪽을 골라 물체 경계를 넘지 않게)
가파름          = 1 − |법선.y|                 // 바닥 0, 벽 1
기울기 마스크   = lerp(1, smoothstep(가파름 하한, 상한, 가파름), 기울기 필터 세기)   // 세기 0 = 수심만 보는 고전 방식
```

**③ 띠 모양 — 노이즈로 가장자리 깨기**

```text
노이즈 = 거품 텍스처(수면 월드 XZ, 천천히 흐름)    // feature/foam-mask의 wave_foam (구름 무늬 회색) 재사용
거품   = smoothstep(노이즈 − 부드러움, 노이즈 + 부드러움, 경계 가까움 × 기울기 마스크)
```

- 경계에 가까울수록 노이즈 문턱을 쉽게 넘어 꽉 찬 흰색, 폭 끝으로 갈수록 노이즈 모양대로 끊긴다.
- 부드러움이 작으면 스타일라이즈드한 단단한 가장자리, 크면 부드러운 띠.

**④ 합성 — 수면 위에 얹는다**

```text
거품 색 = 거품 색(흰색) × 들어오는 빛(환경광 + 햇빛 × 태양 높이)    // 노을이면 거품도 어둡고 따뜻해짐
최종    = lerp(6단계 최종, 거품 색, 거품 × 세기)
```

거품은 수면에 떠 있는 불투명한 것이라 반사와 물속을 둘 다 가린다. 그래서 반사 합성 뒤에 얹는다.

**디버그 뷰**

| 번호 | 이름 | 내용 |
|---|---|---|
| 20 | Foam mask | 최종 거품 양 (흰색 = 거품) |
| 21 | Receiver steepness | 복원한 받는 표면의 가파름 (검정 = 평평, 흰색 = 벽), 물 너머 표면 전체 |

## 4. Acceptance Criteria / Test Plan

**에이전트 검증**

- [ ] 빌드 경고 0, 디버그 레이어 경고 0, 기존 샷 21장 바이트 동일
- [ ] 거품 세기 0 → 6단계 화면과 바이트 동일
- [ ] 거품 픽셀의 정답지 수심(Scene Debug 2)은 모두 폭 이하. 하늘·바닥 없음 픽셀에는 거품 0
- [ ] 기울기 필터 켬: 평평한 수신 표면(정답지 법선 y > 0.9)에 거품 0. 끔: 0.2m 받침대 윗면이 거품으로 덮임 (고전 방식의 문제를 재현)
- [ ] 복원 법선 vs 정답지 법선: 물체 경계를 뺀 픽셀에서 각도 오차 작음 (수치는 측정 후 기록)
- [ ] 폭이 카메라와 무관: 여러 샷에서 거품이 생긴 픽셀의 최대 수심이 같은 폭 이하

## 5. Notes

- **화면 공간의 한계:** 거품은 "이 픽셀에서 물 너머로 보이는 표면"의 수심으로 정한다. 그래서 수면 위로 바깥쪽으로 퍼지는 고리는 그릴 수 없다. 기둥에서 수평으로 30cm 떨어진 수면 픽셀은 물 너머로 깊은 바닥을 보기 때문이다. 띠는 카메라 쪽에서 보이는 잠긴 면에 생긴다.
- **언리얼 대응:** 같은 방식은 머티리얼의 `DepthFade` / `SceneDepth − PixelDepth`. 바깥쪽 고리는 메시 거리장(`DistanceToNearestSurface`)으로 물체까지의 수평 거리를 직접 구할 수 있다. 12단계 이후 비교한다.
- 파도가 생기면(7단계) 수면 높이가 픽셀마다 달라지므로, 수심 계산에 쓰는 수면 높이를 실제 변위된 높이로 바꿔야 한다.
- **6C와의 관계 (사용자 결정 2026-11-07):** 6B는 G-Buffer 없이 깊이만으로 법선을 추정한다 (화면 공간 기법을 직접 이해하기 위해). 6C에서 불투명 패스가 노멀을 저장하는 버퍼를 추가하고, 같은 샷에서 *Depth Reconstructed* ↔ *Stored Scene Normal*을 화질(각도 오차 지도)과 성능(패스별 GPU 시간)으로 비교한다. 6B의 22번 화면과 Scene Debug 4가 그 비교의 출발점이다.
