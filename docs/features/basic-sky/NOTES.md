# basic-sky — Basic 하늘을 한낮 들판으로 (회고 기록)

> 2026-10-03 · feature/basic-sky

캡처 조건은 이전 feature와 같음(1280×720, `t = 12s`, 고정 샷 5개, 무인 모드). 바뀐 건 Basic뿐이라 Basic만 남김.
재현: `WaterShader.exe --capture-feature basic-sky --capture <label>` → `captures/<label>/`, 비교 시트 `compare/` (`make_compare.ps1 -Dir ../basic-sky before step1_field_day step2_retune`).

## 문제 — Basic인데 바다가 노을빛

hdr-env에서 Basic 하늘을 HDR 원본 `grasslands_sunset`으로 바꾼 뒤, **노을 프리셋이 아닌 Basic에서도 수면에 붉은·분홍 빛이 나왔다.**

- **원인:** 하늘 자체가 노을이다. 해가 고도 3.3°에 걸린 연무 속 붉은 해라, hdr-env 도구로 측정한 태양색이 **(0.42, 0.08, 0.01)**로 거의 빨강이었다. 태양 주변 하늘도 분홍이다.
- 물은 하늘을 그대로 반사하고(프레넬로 수평선 쪽은 거의 거울), 해석적 태양 글린트도 그 측정 태양색을 쓴다. 그래서 **반사·글린트·확산광 셋 다 붉은색**이 된다.
- LDR 시절엔 같은 사진이 톤매핑으로 바래 있어서(하늘 채도 0.11) 덜 보였다. HDR로 바꾸면서 실제 색이 살아나(채도 0.40) 문제가 드러난 것.
- 즉 셰이더 버그가 아니라 **입력(하늘) 선택**의 문제다. "Basic = 중립적인 낮 조명" 역할에 노을 하늘이 맞지 않았다.

측정(물 영역 = 화면 아래 60%, 채도 > 0.15이면서 색상 330°~25°인 픽셀 비율):

| 샷 | before 붉은/분홍 |
|---|---|
| ocean_sunward | 4.7% |
| ocean_wide | 2.7% |

## Step 1 — 하늘 교체 (`captures/step1_field_day/`)

### 후보 선정

Poly Haven 카탈로그(API `https://api.polyhaven.com/assets?t=hdris`, 997개)를 필터링:
- 카테고리 `midday` 또는 `morning-afternoon`, `sunrise-sunset`/`night`/`urban`/`indoor` 제외
- 태그·설명에 field/meadow/grass/farm 등, 숲·산·사막·도로 분류 제외

→ 다운로드 순 상위에서 미리보기를 보고 5장으로 좁힘:

| 후보 | 하늘 | 태양 고도(미리보기 추정) |
|---|---|---|
| **belfast_farmhouse** | 파란 하늘 + 구름 조금, 태양 보임 | 약 23° |
| dreifaltigkeitsberg | 맑음, 하늘 고름 | 약 44° |
| horn-koppe_spring | 약간 뿌연 맑음 | 약 60° |
| cloud_layers | 흰 구름 많음 | 약 57° |
| noon_grass | 정오, 진한 파랑 | 80° 이상 |

**선택 기준 = 태양 고도.** 고정 샷(`sunward`, `ocean_sunward`)은 해 쪽을 바라보는데, 해가 너무 높으면 거울 반사 방향이 카메라 발밑으로 가서 글린트가 화면 밖에 생긴다. 정오(80°+) 하늘은 "한낮"답지만 물 셰이더의 핵심인 빛의 길이 안 보인다. → 20~45°가 적합, **belfast_farmhouse(사용자 선택)**.

LDR 버전은 만들지 않음(사용자 결정 — HDR 경로만 쓰므로 필요 없음).

### 변환·측정

```
tools/equirect_to_cube.ps1 -In belfast_farmhouse_4k.hdr -Out assets/textures/env_field_day_hdr.dds -AlignSunYaw 34.5
```

| 항목 | 값 |
|---|---|
| 태양 방향 | 회전 −1.7° → yaw 34.5°, **고도 21.6°** |
| 태양 조도 (태양 법선면) | (10.74, 10.02, 8.48), 휘도 10.06 |
| 하늘 조도 (위쪽 평면, 태양 제외) | (0.475, 0.732, 1.119), 휘도 0.705 |
| 앱 값 (E/π) | 태양 **(3.420, 3.190, 2.698)**, ambient **(0.151, 0.233, 0.356)** |
| key 노출 | 로그 평균 휘도 0.163 → **EV +0.15** |

- 태양색이 R:G:B = 1 : 0.93 : 0.79 — **중립에 가까운 흰 햇빛**(이전 1 : 0.19 : 0.02와 대비).
- 태양 조도 / 하늘 조도 ≈ 14 — 맑은 낮의 전형(이전 노을은 하늘이 태양보다 8배 밝았다). 그림자·확산광이 태양 주도로 바뀐다.

### 코드 변경

- `kEnvironments`에 7번째 항목 `HDR Field day (belfast_farmhouse)` 추가(기존 인덱스 유지 → Sunset/Tropical 프리셋 영향 없음).
- Basic 프리셋: `environment 6`, 태양 yaw/고도·태양·ambient = 측정값(`SplitLinearLight`와 같은 방식으로 sRGB 색 + 강도로 분해), `exposureEV 0.15`.
- `Intensity` 슬라이더 범위 0~3 → **0~5**: 측정된 태양(최대 채널 3.42)이 기존 범위를 넘었다. 드래그하면 3으로 잘려 버리는 문제.

### 결과

반사의 분홍·주황이 사라지고 하늘색이 그대로 비친다. 하지만 **물 몸체가 청록 페인트처럼** 떠 보였다(step1 `oblique`, `ocean_wide` 앞쪽).

## Step 2 — 몸체색 재조정 (`captures/step2_retune/`)

### 문제

몸체색(facing/grazing)은 노을 하늘 조명에 맞춰 고른 값이다. 몸체가 받는 빛을 비교하면:

| | ambient (휘도) | 태양 × N·L (평면) | 노출 배율 | 화면 밝기 ∝ |
|---|---|---|---|---|
| 이전 (노을) | ≈ 1.25 | 0.15 × sin 3.3° ≈ 0.01 | 2^−0.96 = 0.51 | **≈ 0.65** |
| 새 하늘 | ≈ 0.22 | 3.20 × sin 21.6° ≈ 1.18 | 2^0.15 = 1.11 | **≈ 1.56** |

→ 같은 몸체색이 **약 2.4배 밝게** 나온다. 노을에선 ambient가 크고 노출을 낮췄지만, 한낮에선 직사광이 크고 노출이 높다.

### 해결

몸체색을 **linear 값으로 절반**(sRGB 값을 그대로 반으로 나누면 감마 때문에 linear로는 약 4~5배 어두워짐):
facing (0.03, 0.20, 0.21) → (0.015, 0.136, 0.144), grazing (0.02, 0.26, 0.26) → (0.010, 0.181, 0.181).
글린트(power 300, intensity 1 = 물리값)·F0·노멀은 그대로 — 태양 에너지가 측정값으로 들어가므로 따로 맞출 필요가 없다.

## 검증

| 샷 | before 붉은/분홍 | after 붉은/분홍 | after 노란색 |
|---|---|---|---|
| ocean_sunward | 4.7% | **0.0%** | 3.5% |
| ocean_wide | 2.7% | **0.0%** | 0.4% |

- 남은 노란색은 수평선 근처에 비친 **갈대 둔덕**(하늘 큐브맵의 지면 부분)이라 의도된 반사.
- 물 영역 평균 RGB(ocean_wide): before (79, 96, 102) → step1 (77, 115, 121) → step2 (74, 98, 104) — 밝기는 원래 수준으로 돌아오고 색만 중립으로.
- Debug/Release 경고 0.

## 교훈

- **"Basic이 붉다"는 셰이더가 아니라 입력 데이터 문제였다.** 물리 기반으로 바꿀수록 결과는 입력(하늘)을 정직하게 따라간다 — 프리셋의 의도(중립 낮 vs 노을)에 맞는 하늘을 고르는 것도 룩 디자인의 일부.
- 하늘을 고를 땐 예쁜 사진보다 **태양 고도**가 먼저다. 카메라 구도와 맞지 않으면 글린트가 화면에 안 들어온다.
- hdr-env에서 만든 측정 도구 덕분에 태양·ambient·노출은 **수치를 그대로 옮기기만** 하면 됐다. 손으로 다시 맞춘 건 하늘에서 측정할 수 없는 값(물 몸체색) 하나뿐.
- 조명 환경이 바뀌면 "같은 색" 파라미터의 화면 밝기가 몇 배씩 달라진다. 몸체색을 조정할 땐 linear에서 비율로 바꿔야 의도한 만큼만 변한다.
