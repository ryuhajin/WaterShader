# Scene Color & Depth — NOTES

> 2단계 진행 기록. 상태: **에이전트 검증 완료, 사용자 승인 대기**

## 1. 개념 요약

- 물이 아래 색을 읽으려면 **덮어쓰기 전에 복사**해 둔다. 같은 텍스처를 그리면서(RTV) 동시에 읽을(SRV) 수는 없다.
- 깊이 텍스처는 **형식 미정(`R24G8_TYPELESS`)**으로 만든다. 같은 메모리를 깊이 테스트용(DSV)과 셰이더 읽기용(SRV)으로 따로 본다.
- 물은 깊이 테스트는 하되 깊이를 쓰지 않는다. **읽기 전용 DSV**로 묶어야 같은 깊이를 SRV로 동시에 읽을 수 있다.
- 효과 없는 물(투과 모드)은 **물 끈 화면과 바이트까지 같아야** 한다. 영점 조정.

## 2. 패스 순서 (테스트 장면)

```text
1. 하늘 + 불투명 물체 → HDR 색 + 깊이                (쓰기 가능 DSV)
2. CopyResource(HDR 색 → 장면 색 복사본)
3. OMSetRenderTargets(HDR 색, 읽기 전용 DSV) + 깊이 쓰기 끈 상태
4. 물: t3 = 장면 색 복사본, t4 = 장면 깊이를 Load로 한 텍셀씩 읽음
5. t3·t4 연결 해제, 깊이 상태 기본값 → 톤매핑
```

기존 벤치 평면·오션 그리드는 1~5 대신 예전 그대로 그린다.

## 3. 만든 것

| 파일 | 내용 |
|---|---|
| `src/D3DClass.*` | 깊이 `R24G8_TYPELESS` + 쓰기 DSV + 읽기 전용 DSV + `R24_UNORM_X8_TYPELESS` SRV, 장면 색 복사본(RGBA16F), 깊이 쓰기 끈 상태, 리사이즈 시 재생성, 디버그 레이어 메시지 수집 |
| `src/ColorShader.*` | 세 번째 픽셀 셰이더 변형 `SCENE_INPUTS`(+`OCEAN_DETAIL`). 장면 SRV가 주어지면 이 변형으로 그리고 t3/t4에 묶음 |
| `shaders/PixelShader.hlsl` | `#if SCENE_INPUTS`: 장면 색·깊이 `Load`, 투과 모드, 디버그 8(깊이 원값)·9(물 덮임) |
| `shaders/Common.hlsli` | cbuffer 끝에 `g_SceneParams` (x = 투과 모드) |
| `src/Graphics.*` | 테스트 장면에서 2~5단계 순서, View 창 Transmission 콤보, 디버그 모드 2개, CLI 4개 |

**왜 셰이더 변형을 따로 만들었나:** 이 프로젝트의 기존 물 셰이더는 "한 번도 실행되지 않는 분기라도 코드가 늘면 드라이버 명령 배치가 바뀌어 픽셀이 1~4단계 움직인다"는 문제를 겪었다 (ocean-hero NOTES). 그래서 테스트 장면용 코드는 `#if SCENE_INPUTS` 안에만 두고, 기존 프로그램은 한 글자도 바뀌지 않게 했다.

**새 명령줄 스위치**

| 스위치 | 뜻 |
|---|---|
| `--transmission <0\|1>` | 테스트 장면 물: 0 = 예전 불투명, 1 = 투과(기본) |
| `--resize-cycle` | 시작할 때 크기 의존 리소스를 한 번 반 크기로 만들었다가 되돌림 (재생성 검증) |
| `--d3d-selftest` | 디버그 레이어 경고를 일부러 1건 만듦 (로그가 정말 잡는지 확인) |
| (자동) `d3d_messages.txt` | 캡처 세트 폴더에 디버그 레이어 경고·오류 목록 (Debug 빌드만 의미 있음) |

## 4. 에이전트 검증 (2026-10-24)

| 항목 | 방법 | 결과 |
|---|---|---|
| 빌드 | Debug·Release | 경고·오류 0 |
| 기존 장면 회귀 | 기존 샷 21장 vs 0단계 기준 | **21장 바이트 동일** |
| 투과 = 물 끔 | 테스트 샷 5 × 프리셋 3, PNG | **15장 바이트 동일** |

| 디버그 레이어 로그 동작 | `--d3d-selftest` | 의도한 경고 1건 기록됨: "Resource being set to PS shader resource slot 7 is still bound on output!" |
| RTV/SRV/DSV 충돌 | Debug 빌드: 물 덮임(+리사이즈)·깊이 원값·불투명(+기존 샷)·투과 캡처 | **경고·오류 0건** (4회 모두) |
| 물 덮임 | 디버그 9 화면 | 물 밖 기둥 윗부분, 계단 윗단, 승강장 윗면, 전주에는 물이 그려지지 않음 |

캡처 위치 (로컬): `C:\Users\da171\ws-capture\scene-color-depth\captures\`
`regress`, `pass_on`, `pass_off`, `pass_on_resized`, `dbg_coverage`, `dbg_depth_raw`, `dbg_opaque`, `dbg_pass`, `selftest`

**과정에서 고친 것**

- 처음엔 디버그 레이어 로그가 자체 점검에서도 0건이었다. 원인: 캡처가 1장뿐이면 첫 프레임 끝에서 메시지를 모으기 **전에** 파일을 썼다. 파일을 쓰기 직전에도 모으도록 고쳤다. 디버그 레이어가 켜졌는지도 인터페이스 유무 대신 디바이스 생성 플래그로 판단한다.
- 사용자 질문(2026-10-24)으로 두 "깊이" 화면 이름을 나눴다. 1단계 `Scene Debug`는 **Water depth (WP, m)** — 월드 위치 높이로 계산한 수심(미터, 정답지), 선택하면 View 창에 색별 미터 범례가 나온다. 2단계 물 디버그는 **Depth buffer** — 카메라 기준 깊이 버퍼 값.

**검증하지 못한 것**

- 실제 창을 마우스로 늘이고 줄이는 리사이즈는 하지 않았다. `--resize-cycle`은 같은 재생성 코드(`D3DClass::Resize`)를 타지만 창 크기 자체는 그대로다.

## 5. 사용자 검증 안내

**실행:** `.\build\vs2022\Debug\WaterShader.exe` → `1` 키 → Scene = **Water Lab**

| 순서 | 조작 | 정상 | 실패 징후 |
|---|---|---|---|
| 1 | Transmission = **Pass-through** (기본) | 물을 켜도 계단·받침대가 그대로 보임 | 물이 있는 곳만 색·밝기가 미세하게 다름, 테두리가 생김 |
| 2 | **Show Water** 껐다 켜기 | 화면이 전혀 바뀌지 않음 | 조금이라도 바뀜 |
| 3 | Transmission = **Opaque (old water)** | 1단계처럼 물이 아래를 덮음 | — |
| 4 | Debug Mode = **Water coverage** | 물에 잠긴 부분만 파랗게, 기둥·계단 윗부분은 원래 색 | 물 밖 부분까지 파랗거나, 잠긴 부분이 빠짐 |
| 5 | Debug Mode = **Depth buffer** | 거의 전부 하얗고 가까운 것만 살짝 회색 | 까맣게 나옴 (깊이를 못 읽음) |
| 6 | 창 크기를 마우스로 바꾸기 | 1~5가 그대로 | 화면이 깨지거나 멈춤 |

**확인 질문**

- [ ] Pass-through에서 물을 켜고 꺼도 화면이 같다
- [ ] Water coverage에서 물 밖 기둥이 가려지지 않는다
- [ ] Depth buffer 화면을 보고 "깊이 값이 거리와 비례하지 않는다"를 확인했다
- [ ] 복사본이 필요한 이유, 읽기 전용 DSV가 필요한 이유를 설명할 수 있다
