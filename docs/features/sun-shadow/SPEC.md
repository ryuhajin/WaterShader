# Sun Shadow — 9단계 수신 물체의 그림자

> Branch: `feature/sun-shadow` · Status: draft · Updated: 2026-11-09
> waterfront 업그레이드 9단계. 앞 단계: [../refraction/NOTES.md](../refraction/NOTES.md)

## 1. Goal / Visual Target

- **한 문장 요약:** 태양 하나의 **그림자 맵(Shadow Map)** 을 만들어, 테스트 장면의 물체가 바닥·계단·다른 물체에 그림자를 드리운다. 물속 바닥의 그림자는 물을 통해 보이고, 그림자 속 수면에서는 태양 글린트가 사라진다.
- 그림자는 **햇빛(직접광)만** 가린다. 하늘빛(환경광)은 남아서 그림자가 새까맣지 않다.
- 다음 단계(10 코스틱)의 준비: 코스틱은 햇빛이 만드는 무늬라 그림자 속에서 사라져야 한다 (`decisions.md` 2026-10-23 "그림자 맵을 구현한다").
- **스코프 가드 — 만들지 않을 것:** 여러 광원, 계단식 그림자(Cascaded Shadow Map: 장면이 작아 한 장으로 충분, 언리얼 14단계에서), 물이 드리우는 그림자, 수면에서 꺾이는 햇빛의 그림자 이동(굴절된 그림자), 기존 바다 화면 변경, 성능 측정(요청 시만).

## 2. 방법

**① 그림자 패스 (새 패스) — 태양에서 본 깊이**

```text
태양 방향으로 놓은 직교 카메라 (물 영역 + 물체 높이를 감싸는 고정 상자)
→ 테스트 장면 물체를 깊이만 그림 → 그림자 맵 (D32 2048 × 2048)
```

- 패스 순서: **그림자 패스 → 불투명 장면 → (물 깊이 프리패스) → 물**. 앞 패스(그림자 맵)를 뒤의 두 패스가 읽는다.
- 물은 그림자를 드리우지 않는다 (투명).

**② 받는 쪽 — 그림자 비교**

```text
픽셀의 월드 위치 → 태양 카메라로 투영 → 그림자 맵 깊이와 비교
그 깊이보다 멀면 = 태양과 나 사이에 뭔가 있음 = 그림자
햇빛 = 햇빛 × 그림자 비율 (0 ~ 1)     환경광은 그대로
```

- **필터 (Light 창 목록, 사용자 결정 2026-11-09)**: 그림자 가장자리 처리를 셋 중에서 고른다.
  - **Hard**: 비교 1번. 텍셀 모양대로 계단진 가장자리 (기준).
  - **PCF 3 × 3**: 비교를 9번 해서 평균. 하드웨어 비교 샘플러(`SampleCmpLevelZero`)라 한 번에 주변 4텍셀을 보간해 부드럽다. 폭은 어디서나 같다.
  - **PCSS**: 먼저 주변에서 가리는 물체의 깊이를 찾아(blocker search) 받는 면과의 거리로 반그림자 폭을 정하고, 그 폭으로 PCF. 물체 바로 밑은 선명하고 멀어질수록 흐려진다. 태양 크기(각도) 슬라이더로 폭을 조절.
- **바이어스**: 같은 표면이 자기 그림자를 받는 얼룩(shadow acne)을 막으려고 비교 깊이를 조금 민다. 크게 밀면 그림자가 물체에서 떨어진다(peter-panning). 고정 바이어스 + 기울기 비례 바이어스 + 노멀 방향 오프셋을 슬라이더로 두고 둘 사이를 직접 본다.

**③ 물에서의 그림자**

- 물속 바닥·계단: 불투명 장면 셰이더가 그림자를 받으므로 물을 통해 그대로 보인다 (굴절·감쇠도 그대로 적용).
- 수면: 수면 점에서 그림자 맵을 읽어 **태양 글린트**와 물색·거품을 비추는 **햇빛 부분**에 곱한다. 기둥의 그림자가 수면에 떨어진 곳은 반짝임이 사라진다.
- 근사: 햇빛도 수면에서 꺾이지만, 그림자는 꺾이지 않은 햇빛 방향으로 계산한다 (물속 그림자가 실제보다 조금 어긋남. 한계로 기록).

**디버그·도구**

| 이름 | 내용 |
|---|---|
| Scene Debug 5 | 그림자 비율 (흰색 = 햇빛, 검정 = 그림자), 불투명 물체 |
| Debug Mode 29 | 수면의 그림자 비율 |
| Light 창 **Shadows** 대분류 | 켬/끔, **Filtering** 목록 (Hard / PCF 3×3 / PCSS) + PCSS 태양 크기, **Bias** 목록 (None / Constant / Slope-scaled / Normal offset / All, 기본 All) + 고른 바이어스의 세기 슬라이더, 그림자 맵 미리보기 |
| 움직이는 시험 상자 | View 창 체크박스: Water Lab에 천천히 움직이는 상자 (그림자가 따라가는지) |
| CLI | `--shadows on\|off`, `--shadow-filter hard\|pcf\|pcss`, `--shadow-bias none\|constant\|slope\|normal\|all` |

## 3. Acceptance Criteria

**에이전트 검증**

- [ ] 빌드 경고 0, 디버그 레이어 경고 0, 기존 샷 21장 바이트 동일
- [ ] 그림자 끔 → 8단계 화면과 같음
- [ ] 위를 향한 평평한 면에서, 위로 막는 물체가 없는 곳의 그림자 얼룩(acne)이 0에 가까움 (바이어스 0과 비교)
- [ ] 바이어스 목록의 각 항목에서 얼룩·떠 있는 그림자가 어떻게 달라지는지 같은 샷으로 캡처 (None / Constant / Slope / Normal / All)
- [ ] 필터 세 가지(Hard / PCF / PCSS)를 같은 샷으로 캡처. PCSS는 기둥 밑동 근처가 먼 끝보다 선명함 (가장자리 폭 측정)
- [ ] 그림자 속 픽셀이 환경광 밝기 이상 (새까맣지 않음)
- [ ] 수면 그림자 속에서 글린트가 사라짐 (같은 샷 그림자 켬/끔 비교)
- [ ] 움직이는 상자의 그림자가 따라감 (서로 다른 시간 캡처)

**사용자 검증**

- [ ] 기둥·계단·받침대의 그림자가 바닥과 물속 바닥에 보인다
- [ ] 태양 방향을 바꾸거나 시험 상자를 움직이면 그림자가 따라간다
- [ ] 바이어스를 0으로 하면 얼룩이, 너무 크면 떠 있는 그림자가 생기는 이유를 설명할 수 있다
- [ ] Hard / PCF / PCSS의 차이(가장자리 계단, 고른 부드러움, 거리에 따른 부드러움)를 설명할 수 있다

## 4. Notes

- 언리얼 대응: 디렉셔널 라이트의 Cascaded Shadow Map(또는 Virtual Shadow Map). 14단계에서 엔진 그림자를 쓴다.
- 성능 측정은 하지 않는다 (요청 시만).
